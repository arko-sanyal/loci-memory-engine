# Commit and file signing

This repo signs commits with SSH (not GPG) using a dedicated key
(`arko-sanyal-loci-signing`, fingerprint `SHA256:yq2hV/IogKRPoRJeYXapos1gXtEkpALsZspaz7CdB74`)
registered to the `arko-sanyal` GitHub account as a signing key. From this commit forward, every
commit made in this checkout is signed automatically (`commit.gpgsign = true`,
`gpg.format = ssh` in this repo's local git config).

## Verifying a commit

```bash
git config --local gpg.ssh.allowedSignersFile .git-signing/allowed_signers
git log --show-signature -1
```

Or check GitHub directly — a signed, key-verified commit shows a "Verified" badge next to it on
github.com.

## Verifying `Sonnet-01.md` directly (no git needed)

`Sonnet-01.md.sig` is a detached SSH signature over the exact bytes of `Sonnet-01.md` as of the
commit that added it. To verify:

```bash
ssh-keygen -Y verify -f .git-signing/allowed_signers -I arko-sanyal@github -n file \
  -s Sonnet-01.md.sig < Sonnet-01.md
```

A successful verification prints `Good "file" signature for arko-sanyal@github ...`. If
`Sonnet-01.md` is ever edited, this verification will fail — which is expected, since
`Sonnet-01.md` is meant to be immutable (see `CLAUDE.md`); a new `Sonnet-02.md` with its own
`.sig` should be created instead of altering this one.

## What this does and does not prove

- **Does prove:** the signed commit / signed file was produced by whoever held the private half
  of this key at signing time, and the content has not changed since (any edit invalidates the
  signature).
- **Does not prove:** with absolute certainty that Arko Sanyal personally typed the content — the
  private key lives in this development environment, generated by an AI agent (Claude) acting on
  Arko's request, so the guarantee is only as strong as this environment's own security. This is
  a deliberate, disclosed tradeoff (see the commit history / `Sonnet-01.md` for the discussion),
  not an attempt to overstate what's actually guaranteed.
